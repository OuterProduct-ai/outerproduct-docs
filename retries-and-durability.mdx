title: "Retries and durability"
---

An OuterProduct Run forms a computation graph. The top-level `client.run()` creates a new Run and its root Call. Inside that Call, the scoped client can create child Calls within the same Run.

This hierarchy allows OuterProduct to track each Call independently. For example, in the following code, the `pipeline` call orchestrates a 2-step workflow (first, `prepare_data` , then `train_model` ). Every function receives an OuterProduct client as its first argument. A function can ignore it, as `_client` does above, or use it to create more Calls.

Breaking an application into Calls gives OuterProduct durable boundaries where work can be retried, tracked, and checkpointed.

```python
import outerproduct_sdk as op


image = op.Image.from_registry("python:3.12-slim")


def prepare_data(_client, records):
    return [record.strip() for record in records]


def train_model(_client, records):
    return {"examples": len(records)}


def pipeline(client, records):
    prepared = client.run(
        fn=prepare_data,
        args=(records,),
        image=image,
    ).wait()

    return client.run(
        fn=train_model,
        args=(prepared,),
        image=image,
    ).wait()


client = op.init()

run = client.run(
    fn=pipeline,
    args=(["To be", "or not to be"],),
    image=image,
)

model = run.wait()
```

## Retrying a Call

Use `RetryStrategy` to specify the maximum number of Attempts for a Call:

```python
run = client.run(
    fn=train_model,
    args=(training_data,),
    image=training_image,
    gpu_type="L4",
    retry_strategy=op.RetryStrategy(max_attempts=3),
)
```

`max_attempts` includes the first Attempt. In this example, OuterProduct can try the Call up to three times. If no retry strategy is provided, the Call receives one Attempt and is not retried automatically. Each Call defines its own retry strategy; a parent and its children can therefore use different limits.

## Durable execution

OuterProduct checkpoints work at Call boundaries. Once a Call succeeds, its result is stored as part of the Run. If a parent Call fails and is retried, it begins executing again. When it reaches a child Call that already succeeded, OuterProduct returns the stored result instead of executing that child again. 

A long workflow can therefore recover from a failure without repeating all of its successful work. For example:

```text
Attempt 1
├── prepare_data   ✓ completed
├── train_model    ✓ completed
└── publish_model  ✗ failed

Attempt 2
├── prepare_data   ↪ reuse result
├── train_model    ↪ reuse result
└── publish_model  ✓ completed
```

<Warning>
  If a Call fails halfway through its function, its next Attempt starts that function again from the beginning. Split expensive or important stages into separate Calls when you want them checkpointed independently.
</Warning>
