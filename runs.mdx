A Run is a remote execution of your code on OuterProduct. It starts with a single function call and can include additional child function calls launched from within it. Each call can have its own image, compute resources, and configuration.

## Runs, Calls, and Attempts

OuterProduct tracks execution at three levels: 

- **Run:** The complete execution, including the initial function call and any calls it launches.
- **Call:** One function invocation with its arguments and execution settings. Every Run starts with a root Call.
- **Attempt:** One try at executing a Call. Retrying a Call creates another Attempt for that Call within the same Run.

A Run can contain many Calls, and each Call can have multiple Attempts. The dashboard shows this structure alongside execution status and logs.

See [Retries and durability](/retries-and-durability) for retry configuration and behavior.

## Running a function

To create a Run in OuterProduct, create a Python function that takes an OuterProduct  `client`  as its first parameter. Then, submit your function using `client.run()`, specifying the function to run, along with its arguments and compute requirements. 

```python
import outerproduct_sdk as op

def sum_batch(client, values):
    return sum(values)

client = op.init()
run = client.run(
    fn=sum_batch,
    args=([1, 2, 3],),
    image=image,
)

print(run.wait())  # 6
```

OuterProduct supplies the function’s `client` argument automatically. Positional arguments supplied through `args` follow it; named arguments can be supplied through `kwargs`.

`client.run()` returns a `Run` handle after submission, without waiting for execution to complete. `run.wait()` blocks until the Run completes and returns the function’s result. It raises `RunFailed` if the Run fails or is cancelled.

In addition to the function, arguments, and image, `client.run()` accepts execution settings for the root Call:

- [Hardware](/hardware) resources, including CPU and GPU requirements.
- [Environment Variables](/env-vars)
- [Volume mounts](/volumes)
- [Retry settings](/retries-and-durability)

### Arguments and results

OuterProduct serializes functions, arguments, and return values using `cloudpickle`. Arguments and results can be Python objects, provided they support serialization.

<Warning>
  Large arrays, datasets, model weights, and other large inputs or outputs are often better stored in a [Volume](/volumes) and managed through volume mounts.
</Warning>

## Nested calls

In the example above, we created a Run to execute a single function remotely using client.run(). This Run only consisted of a single function Call. 

However, the true power emerges when we nest XYZ.. The  client parameter supplied to a running function connects it to the current Run. Calling its `run()` method creates a child Call within that Run. This allows for nesting an arbitrarily deep computational graph of function calls within a single Run.

```python
def sum_of_squares(client, left, right):
    first = client.run(
        fn=square,
        args=(left,),
        image=image,
    )
    second = client.run(
        fn=square,
        args=(right,),
        image=image,
    )

    return first.wait() + second.wait()


run = client.run(
    fn=sum_of_squares,
    args=(3, 4),
    image=image,
)

print(run.wait())
# 25
```

This creates one Run with three Calls: the root Call to `sum_of_squares` and two child Calls to `square`.

Both child Calls are submitted before the parent waits for their results, allowing them to execute concurrently. Inside the function, `client.run()` returns a `Call` handle, which provides the same `.wait()` interface.

Each child Call specifies its own image and execution settings. Compute resources, environment variables, volume mounts, and retry settings are configured separately for each Call.

Child Calls still running when their parent function returns are cancelled. In this example, the parent waits for both children before returning its result.

## Mapping over inputs

`client.map()` applies a function to a collection of inputs concurrently. It waits for all results and returns them in input order.

```python
def sum_of_squares(client, values):
    results = client.map(
        square,
        values,
        image=image,
    )
    return sum(results)


run = client.run(
    fn=sum_of_squares,
    args=([1, 2, 3, 4],),
    image=image,
)

print(run.wait())
# 30
```

Each input becomes a separate argument to `square`. Here, the Run contains the root Call to `sum_of_squares` and four child Calls.

As with `client.run()`, the execution context determines where the work belongs. Inside a running function, `client.map()` creates child Calls in the current Run. From local code, it creates a separate Run for each input.

## Async usage

The SDK’s execution methods also have asynchronous forms, available through `.aio()`. These integrate with Python’s `async` and `await`:

```python
import asyncio

async def main():
    run = await client.run.aio(
        fn=square,
        args=(7,),
        image=image,
    )
    result = await run.wait.aio()
    print(result)


asyncio.run(main())
```

Functions executed by OuterProduct can also use `async def`. Within an async function, `await client.run.aio()`, `await call.wait.aio()`, and `await client.map.aio()` provide the same execution behavior without blocking the function’s event loop.
