A Run is a remote execution of your code on OuterProduct. It starts with a single function call and can include additional child function calls launched from within it. Each call can have its own image, compute resources, and configuration.

## Runs, Calls, and Attempts

OuterProduct tracks execution at three levels:

- **Run:** The complete execution, including the initial function call and any calls it launches.
- **Call:** One function invocation submitted through the SDK with its arguments and execution settings. Every Run starts with a root Call.
- **Attempt:** One try at executing a Call. Retrying a Call creates another Attempt for that Call within the same Run.

A Run can contain many Calls, and each Call can have multiple Attempts. The UI shows this structure alongside execution status and logs.

See [Retries and durability](/retries-and-durability) for retry configuration and behavior.

## Running a function

To create a Run in OuterProduct, write a Python function that takes an OuterProduct  `client`  as its first parameter. Then, submit your function using `client.run()`, specifying the function to run, along with its arguments and compute requirements. 

```python
import outerproduct_sdk as op

def sum_batch(client, values):
    return sum(values)

client = op.init()
image = op.Image.from_registry("python:3.13-slim")

run = client.run(
    fn=sum_batch,
    args=([1, 2, 3],),
    image=image,
)

print(run.wait())  # 6
```

OuterProduct supplies the function’s `client` argument automatically. The remaining positional arguments can be supplied through the `args` parameter, and named arguments can be supplied through `kwargs`.

`client.run()` returns a handle to the Run after submission, without waiting for execution to complete. Calling `.wait()` blocks until the Run completes and returns the function’s result. 

In addition to the function, arguments, and image, `client.run()` accepts various execution settings for the root Call:

- [Hardware](/hardware) resources, including CPU and GPU requirements.
- [Environment Variables](/env-vars) for the execution runtime.
- [Volumes](/volumes) to mount in the remote container's filesystem.
- [Retry settings](/retries-and-durability) for the root Call. 

### Arguments and results

OuterProduct mounts the source containing each function and imports the function by name. Arguments and return values are serialized using `cloudpickle` and can be any Python objects it supports.

<Note>
  Large arrays, datasets, model weights, and other large inputs or outputs are often better stored in a [Volume](/volumes) and managed through volume mounts.
</Note>

## Async usage

The `.aio()` interface allows SDK operations to be awaited without blocking the calling event loop.

```python
import asyncio


async def main():
    run = await client.run.aio(
        fn=sum_batch,
        args=([1, 2, 3],),
        image=image,
    )
    result = await run.wait.aio()
    print(result)  # 6


asyncio.run(main())
```

`await client.run.aio()` returns a handle after submission. `await run.wait.aio()` waits for the result.

Functions executed by OuterProduct can also use `async def`. Inside an async function, `client.run.aio()`, `call.wait.aio()`, and `client.map.aio()` provide awaitable versions of the same operations.
