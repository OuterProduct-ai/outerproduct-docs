OuterProduct is AI infrastructure built around **Liquid Execution**: you define what your application does, and OuterProduct handles where and how it runs. Build workloads that go:

- **Wide:** Run work in parallel across many CPUs and GPUs.
- **Deep:** Run long sequences of steps that recover from failures.
- **Heterogeneous:** Mix hardware, dependencies, and runtime environments.

There is no more need to adapt your code to the underlying infrastructure. You can now run anything, anywhere, for as long as it takes. 

## How does it work?

OuterProduct packages your Python code into containers, runs it on cloud infrastructure, and scales capacity with demand. You define dependencies, environments, and hardware requirements directly in code—no servers to manage.

As your application runs, OuterProduct tracks its graph of calls, checkpoints completed work, and retries failed steps. Execution picks up where it left off, without repeating successful work.

OuterProduct turns your Python code into containerized workloads and runs them on cloud infrastructure. Capacity adjusts automatically as demand changes, so you do not need to provision or manage servers. Dependencies, runtime environments, and hardware requirements are all specified directly in code.

When your application runs, it creates a computation graph of calls . OuterProduct tracks progress across this graph, retries failed work, and checkpoints completed work. If a failure occurs, execution can resume without repeating work that has already succeeded, making the application durable from end to end.

## What can you do with it?

Liquid Execution makes it possible to build applications such as:

- Multi-agent systems operating over large datasets, with automatic retries and fine-grained access to compute, data, and artifacts.
- Model training and hyperparameter searches distributed across GPUs, with managed checkpoints and evaluation artifacts.
- Long-running data and inference pipelines that resume after failures without repeating completed work.
