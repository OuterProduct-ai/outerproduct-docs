---
title: "Volumes"
---

Volumes provide access to object storage through OuterProduct. They can be used to store datasets, model weights, and other outputs that persist across runs, with contents accessible through the SDK or mounted as files inside a function.

## Creating a volume

`client.create_volume()` creates a volume and returns a `VolumeHandle`. OuterProduct manages the underlying object storage by default.

```python
import outerproduct_sdk as op

client = op.init()
volume_handle = client.create_volume("datasets")
```

`client.get_volume()` returns a handle to an existing volume:

```python
volume_handle = client.get_volume("datasets")
```

## Reading and writing data

`VolumeHandle` provides methods for reading and writing objects through [obstore](https://developmentseed.org/obstore/).

```python
from pathlib import Path

volume_handle.put("training.csv", Path("training.csv"))

result = volume_handle.get("training.csv")
Path("downloaded.csv").write_bytes(bytes(result.bytes()))
```

`put()` accepts bytes, local files, and streams. `get()` returns a result whose contents can be read into memory with `.bytes()` or consumed as a stream. When using these methods, all paths should be specified relative to the volume's root.

The handle also supports other [standard methods](https://developmentseed.org/obstore/latest/getting-started/#configuration) for interacting with an object store, including listing objects, inspecting metadata, copying, renaming, and deleting data.

```python
listing = volume_handle.list_with_delimiter()
metadata = volume_handle.head("training.csv")

volume_handle.copy("training.csv", "archive/training.csv")
```

## Mounting a volume

The `volumes` argument to `client.run()` maps filesystem paths to volume handles. At runtime (and provided the caller is permitted to the function can access the volume’s contents at the specified path:

```python
def count_rows(client):
    import csv

    with open("/data/training.csv") as file:
        return sum(1 for _ in csv.DictReader(file))


result = client.run(
    fn=count_rows,
    image=image,
    volumes={"/data": volume_handle}, # count_rows can access
)

print(result.wait())
```

The same volume can be mounted by multiple calls, including calls created with `client.map()`. Nested calls must declare their own volume mounts.

Mounting requires both read and write access to the volume.

### Supported file operations

Mounted volumes support reading files and sequential writes to new files. They do not support in-place edits, appending, or atomic renames.

## Connecting an external object store

Existing S3 buckets, Google Cloud Storage buckets, and Azure Blob Storage containers can be registered as OuterProduct Volumes. Registration connects a volume to the storage without copying its contents.

An S3 volume specifies a bucket and a stored AWS credential:

```python
credential = client.get_secret("aws-storage")

volume_handle = client.create_volume(
    "external-datasets",
    provider=op.VolumeProvider.S3(
        bucket="my-bucket",
        prefix="datasets/",
        region="us-east-1",
        credential=credential.name,
    ),
)
```

With this prefix, `training.csv` in the volume corresponds to `s3://my-bucket/datasets/training.csv`. Without a prefix, paths are relative to the bucket’s root.

Cloud credentials are stored as typed [Secrets](/governance/secrets), separately from the volume configuration.
